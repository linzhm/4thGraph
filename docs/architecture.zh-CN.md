# 4thGraph 架构与验收

[English](architecture.md) · [Forth 基线](language/README.md)

4thGraph 将高层 Forth 程序编译成 BSV Script，并为支持的工作流产生交易计划。程序表达值怎样产生、由谁授权、本次花费须约束哪些状态和输出，以及哪里必须原子执行或可独立提交。编译目标提供适用交易版本、链规则、签名覆盖与成本策略。

| 层 | 职责 |
| --- | --- |
| Forth 与标准库 | [Forth 基线](language/README.md)固定源码语义、语法和公共词。PELS 是交易约束模板族。R1 是所有者授权示例，用公钥哈希锁定，并验证当前花费的签名。 |
| 编译器与规划器 | 检查源码契约，比较合法交易切割，按调用点已证事实选择实现并链接 Script。交付精确 Script 字节和所选构建入口对应的元数据。 |
| 组装器与钱包 | 按实际前序绑定交易，准备所选路径的待签材料，按需请求宿主授权，并组装见证。使用编译期选定的 Script 和清单。钱包可搭配项目 WASM。 |
| 独立评估 | 固定向量评估纯公式。固定版 chain-gang 对照实际父交易验证完整花费。按需记录 BSV Node 复核。分别记录估算、离线验证、入池与确认结果。 |

## 开发与调优

从最高层 Forth 开始，固定语义、目标、依赖与夹具。并行探索可独立归因的选择。A 固定源码和模块绑定，比较公式内部的编译计划与有限 pass 次序。B 固定编译计划，比较保持同一契约的 Forth 算法实现。调用点选型固定高层源码和模块内部 pass，比较特定调用点可用的实现。交易布局在相同覆盖契约下比较合法的交易和见证安排。Agent 从每个空间选择有预算的候选批次。固定评估器给出验收判定和实测成本。局部入围项只在依赖和契约兼容时组合，并用同一调用方或完整花费复测。

类型化 AST 和依赖图记录结果怎样推导。源码快照、规范化约束、构建计划、精确 Script 和片段分别保存摘要。字节哈希定位产物，源码和构建记录说明它由哪些修改产生并支持重放。多个计划即使得到相同字节，也各自保留来历。

分任务验收已覆盖宽整数、重复哈希和曲线调用。[优化路径与重放](optimization-paths.zh-CN.md)

### 在调用点选择模块实现

Forth 通过公共词表达要完成的操作。编译器在解析词和输入事实后，按调用点选择一个已登记的实现，再对该实现做图优化、栈调度和链接。同一个词的两个调用点可以绑定不同实现。可用已知常量、范围或坐标表示选择专用内核，在相邻调用之间保留共同表示以省转换，也可在重复调用的区域内比较展开、查表和共用中间量。首个切片聚焦单个调用点的专用内核选择。

- **操作与实现契约。** 用语义操作和参数域标识公共词，例如指定曲线、域和结果等价关系的点加。实现登记版本和摘要、输入与输出的表示和栈效果、适用目标、前提和可观察的失败行为。调用点记录源码位置和展开实例，必要时把表示转换或守卫作为候选的一部分。上层观察到的输出编码也须符合原契约。
- **优化路径与组合边界。** 签名方案和曲线分别匹配。同为 ECDSA 的 P-256 与 secp256k1 验签走各自的曲线路径。通用算术规则仍可在选定的内核内使用，前提是该内核的语义和范围满足规则。一次计划在同一调用点或区域选择一条实现路径。共享同一区域的候选按替代路径比较，有守卫的实现按包含所有分支的一条路径计量。多个实际调用区域的候选只有在表示、输入输出及覆盖契约相容时才组合，并重新链接、验证和计量。
- **先判合法，再算代价。** 常量或表项构造、每条相关路径在调用前执行的检查，以及从这些事实推出的范围可以证明前提。类型声明表达约束，输入分布提示指导搜索，合法性须有可核验的证据。证据不足时保留通用实现。带守卫的专用实现须覆盖其余路径并保持边界行为。对合法候选分别计算内核、转换、守卫、额外栈槽、静态展开次数和重复数据的成本。实际执行次数按路径计算。先用估算筛选，再实测链接后 Script、栈峰值、编译耗时和适用的完整交易路径。
- **计划和回执。** 一份计划记录调用点、语义操作、证明来源、候选及排除原因、选中的实现版本和摘要，并关联已有的公式与栈调度计划、精确 Script 和回执。Agent 可提议要比较的候选，固定评估器判定结果。按固定绑定重放选中计划，源码相同的构建也能定位到各次不同的模块选择。

仓库中已有 P-256 的项目级先例。R1 的分表构造能证明固定基点表的非零项 `Z=1`，零项单独处理无穷远。联合表含可变点的条目没有同一证明，所以不能沿用这个仿射替换。记录的 `split-4-affine-g` 整锁省了 448 B，同时 OTDA 重建程序增加 128 B，说明调用点节省需要带到完整目标复测。这个先例由项目编译器显式实现，供通用选型设计参考。[P-256 扫描和选型](../projects/p2pkh-r1/forth/msm_compiler.py) · [已记录的构造对比](../projects/p2pkh-r1/forth/history.md)

首个独立验收用中性的点加调用方，重用标准库的完整射影点加和右操作数为仿射点的实现。固定同一份高层 Forth、编译 pass 和夹具，分别给出已证有限且 `Z=1`、以及无此事实或可能为无穷远的调用点。对前者编译通用和专用两种绑定，对后者验证专用绑定被排除。另验证异曲线内核或在同一调用点提交两种绑定会被拒绝。各合法路径都对照独立的点加结果，并覆盖同点、逆点、无穷远、转换和栈契约。最后用同一调用方和固定版 chain-gang 复测花费，记录排除原因和可复跑的选型计划。[现有标准库点加](../src/fourthgraph/stdlib/secp256k1.fth)

存在区域交互的方法用有界的有序对进行探索。方法声明作用区域和前提，每一步接收上一状态。5×5 实验按行后接列，反向顺序保留为另一格。多种方法依赖同一前提时，可再冻结一个已满足该前提的起点。产物字节相同的计划分别追踪，精确产物与夹具都一致时复用验收。根据目标分别排已验证花费的成本。[R1 矩阵示例](optimization-paths.zh-CN.md#r1-有序方法探索)

显式实验可以把有序对扩展为更长的序列。它在各状态尝试当前合法的方法，直到没有新状态或达到预算。扩展去重依据决定后续适用性的完整状态，包括绑定、表示和已证事实。回执保留汇合的路径边，并可在同一预算下复跑实验。

通用命令 `4thgraph SOURCE --entry WORD` 使用固定版本的编译器和 `--optimize safe` 等显式选项构建。实验层可提出有序计划。固定计划记录编译器版本、源码和导入摘要、精确方法顺序及预期产物摘要。重放按相同前提只执行这一个序列。R1 的曲线窗口、交易字节目标、计划和夹具归项目目录管理；项目入口组合通用编译器和有序方案执行器。[R1 固定方案](../projects/p2pkh-r1/forth/README.md#同一份-baseline-lock-的自动选型)

## CPN 规划与验证

类型化 Forth 程序定义一张逻辑有色 Petri 网（CPN）。Place 描述令牌承载的状态、编码及其来源。迁移声明所需授权、断言和可观察效果。阶段规划器比较交易布局，支持在命名路径中为各迁移分配后端和职责。两阶段编译器用实际输入和有序输出核对同一个中间值，从而组合独立证明。嵌套证明依赖先保留在报告中，待后端实际约束该依赖后才能部署。SPV Token 设计从 CCTP 已验收的交易出发，用它们的实际父 outpoint 和有序输出作为共同验收夹具。 [命名路径](design/README.zh-CN.md#命名路径与证明依赖) · [SPV Token 编译设计](design/README.zh-CN.md#spv-token-cpn) · [可执行的 CPN 示例](../projects/workflow-examples/README.zh-CN.md#compile-and-replay-a-cpn)

逻辑 CPN 定义程序骨架，Forth 词定义迁移内的局部计算。生产方的输出端口和消费方的输入端口由同一个类型化 Place 相连。规划器按具体布局选择交接方式。融合输入可通过栈交接，串行布局则由下一笔交易消费后继 UTXO，并核对实际 prevout 与锁中编码的状态。工作台可查看两张图以及复放输出实际承载的字段。 [工作台指南](../skills/4thgraph/references/cpn.zh-CN.md#使用交互工作台)

逻辑模型支持多个类型化端口、Token 数量和循环。离线编辑器可保存节点要求。有界分析器探索 Token 数量并列出假设和截断边界。当前编译适配器接受单条公开状态链、授权角色和支持的证明及见证策略，遇到尚无执行实现的要求或图结构会拒绝。CCTP 归档适配器可重建实际交易和 outpoint 关系供检查。 [模型、编译和归档命令](../skills/4thgraph/references/cpn.zh-CN.md#使用交互工作台)

在已声明的边界和参与者假设下，检查状态可达、后继可获授权以及指定出口可用。转移循环可以持续执行。具体交易的依赖成环，或构造器需要循环内联完整锁时，淘汰该构建。另检查每轮的锁、见证和下一笔所需历史是否增长。定长后继模板仍需有界的来源证据。

每个候选把源码断言映射到实际生成的检查，并记录每个操作数的认证来源。同笔内切分时，各部分核对共同的输入和有序输出承诺。跨交易切分时，用实际中间 UTXO 交接认证状态，并保留声明的提交与恢复规则。通过筛选后按整条花费路径排序，计入资金交易和重建。固定选中计划、适用的电路及公开接口、验证密钥、精确锁字节和独立复放结果。花费时选择后端需要已部署的锁预先授权相应分支。 [候选探索与报告](design/README.zh-CN.md#cpn-探索与候选报告)

## 构建与花费的交接

- **独立编译。** `4thgraph SOURCE --entry WORD` 输出 Script 字节、栈签名，以及源码与产物摘要等构建元数据。
- **工作流构建。** 构建报告描述所选布局、交易图和输出 Script。用 `--cpn-plan` 导出规范化交易计划。
- **钱包项目包。** 版本化项目包将精确的锁模板和指令清单与 WASM 模块、manifest 和可执行夹具配对。清单记录适用的模板参数槽和签名锚点。运行项目包验证后生成测试回执。

钱包模块通过 `recognize`、`prepare_spend` 和 `assemble_unlock` 使用实际 prevout 与选定的命名路径。宿主核对请求并按需签名。完整交易和实际父交易交给独立引擎验收。

功能 Profile 标识所支持的模板族，模板版本标识获准的精确字节与见证布局，候选身份绑定一次拟议花费。旧输出继续由已认可的旧版本识别。清单按路径记录摘要算法、链上下文和 `scriptCode`。
