# P2PKH-R1

[English](README.md) · [BSV Script Lab](../../README.zh-CN.md)

## 开发入口

**[钱包 SDK 快速上手](docs/sdk.zh-CN.md#quickstart)** · [统一钱包 SDK](../../sdk/README.zh-CN.md#quickstart)

生成 P-256 收款脚本并签署已审批的付款。统一客户端支持逐输入签名和 Chronicle OTDA。

[版本历史](#version-history) · [协议规范](docs/spec.zh-CN.md) · [安全分析](docs/developer.zh-CN.md#security) · [复现与验证](reference/acceptance.md) · [交易成本](#完整交易与栈测量)

P2PKH-R1 用未压缩的 secp256r1（P-256）公钥的 HASH160 锁定 BSV 输出。付款人只需填入 20 字节收款人哈希。花费时，钱包提供公钥和当前输入的一份经校验的 64 字节 `r || s` 签名。

## 使用场景与取舍

当已有 P‑256 设备或签名服务可为 BSV 付款授权时，用普通 R1 验证钱包接入。例如分别复放两类设备：接收预先计算摘要的设备，以及内部执行 SHA‑256 的设备。处理资金前要核对设备接收的数据和签名编码。钱包的各签名进程共用持久化的签名随机数历史。[设备接入](docs/sdk.zh-CN.md#设备签名和逐输入付款)

R1 在入金时创建完整的付款锁。需要从到账的 UTXO 直接发起普通签名付款时，可采用这条路径，并按钱包策略等待确认。若更看重入金输出体积，钱包也能安排独立的启用交易，则可评估 Deferred。[Deferred 流程](../p2pkh-r1-deferred/README.zh-CN.md)

## 当前模板

参考钱包用 46,302 字节的 v0.2.0 模板新建输出，也能花费已有的 v0.1.0 输出。两个模板的收款人槽位都在偏移 208 至 227，也都支持 ForkID 与 Chronicle OTDA 的全部 12 种签名类型。钱包通过核对实际上一输出的固定字节识别模板。[v0.2.0 模板](template/v0.2.0/template.hex) · [二进制布局](template/v0.2.0/layout.json) · [v0.1.0 模板](template/template.hex)

普通付款使用 ForkID ALL（`0x41`），每个解锁为 326 字节。两进两出夹具从 v0.1.0 的 119,934 字节降到 v0.2.0 的 93,374 字节。Chronicle 激活后可以按需使用 OTDA。对版本 2 交易，参考钱包可以在 OTDA ALL 下重建可识别的输出，在配对 SINGLE 下只重建同索引输出。无配对的 SINGLE 走伴随验签。

## Forth 探索版

Forth 源码 `r1.fth` 逐字节复现完整的 v0.2.0 锁。v0.3.0 在 263 处内部倍点各省 2 B，整锁共省 526 B。锁在见证进入曲线点运算前校验输入。用同一节点复放时，v0.2.0 基线、v0.3.0 和 66,265 B 的 sCrypt 同算法内核版都完成了 ForkID ALL、OTDA ALL 和配对 OTDA SINGLE 付款。[Forth 源码与复跑](experiments/forth/README.md)

## 钱包接入

统一 SDK 支持在 TypeScript、Rust、Go 或 Python 中收款并发起普通 ForkID ALL 付款。签署已经组装的交易或混合交易时，用 `signInput` 为所选输入指定 sighash。使用 Chronicle OTDA 时提供链上下文。调用签名器前，先核对所有 outpoint、金额和脚本，再审批输出和总手续费。[SDK 指南](docs/sdk.zh-CN.md) · [Python 参考钱包](reference/README.md)

```sh
cd projects/p2pkh-r1/reference
python -m pip install -r requirements.txt
python generate_lock.py --owner-hash160 "${R1_OWNER_HASH160:?请设置收款公钥哈希}"
bash verify.sh
```

详见[协议规范](docs/spec.zh-CN.md)、[验收矩阵](reference/acceptance.md)和[付款向量](template/v0.2.0/spend-all.json)。向量密钥是公开测试数据。独立复核和硬件设备验证仍待完成。
