# CCTP 与 BSV 储备桥开发计划

草案 · 2026-11-24

以 [协议规格](bsv-usdc-bridge-spec.md) 和 [实现清单](bsv-usdc-token-checklist.md) 为准。第一条交付路径是独立测试储备到 BSV regtest，再接入跨链测试网。CCTP 用于受支持网络间的原生 USDC 调拨。Circle 合作接口、域注册及生产运营责任以 X01–X04 的确认结果为准。

现有 [Groth16 回归](../../groth16/docs/regtest.md) 可作为出证和交易构造基线。当前金额规则有宿主侧检查，前序证明也由宿主验证。验收时必须区分宿主参考模型、真实电路、BSV Node 和跨链适配器各自验证了什么。

## 里程碑

| 阶段 | 实现范围 | 验收条件 |
|---|---|---|
| 0 · 资产和交易语句 | R01、R04、R12。固化资产描述符、确定性编码、输入 outpoint 和输出 vout、操作类型、数量上限与验证密钥身份。确定实际交易摘要与电路公开输入的绑定，包括共享验证器位置和各代币输入的依赖。 | 参考编码器、交易构造器和电路测试向量产生一致摘要。调整父 outpoint、排序、金额、模板、网络或验证器承诺后，旧证明无法授权交易。明确实际交易金额与资产最小单位分别计量。 |
| 1 · 入金和合法铸造基例 | R02、R03。实现测试储备事件、入金证明和 BSV 铸造路径。选择每个资产发行锚下的串行铸造状态 UTXO 为初版候选，继承已用事件承诺并验证未使用及插入。记录吞吐与争用，供后续评估分片。 | 两笔不同入金可先后铸造。同一事件被重签、并发提交、服务重启后再提交，都只能成功一次。错域、错资产、未确认、错收款人或数量由对应验证层拒绝。 |
| 2 · 代币证明与钱包验收 | R04、R12、R13。以铸造为基例，让电路约束真实父输出、前序证明、持有人授权所在验证层、金额守恒和后继锁。从单父证明走到多个独立父证明。钱包验证指定 vout、协议身份及已确认交易的 Merkle 包含，并独立查询已知花费状态。 | 同一发行的 1→2、2→1 和来自不同父交易的 2→2 在节点入块。拒绝复制真锁、假父证明、重复或遗漏槽位、替换共享验证器、错误后继和超额输出。记录一个证明可服务哪些输入及每个输入如何绑定。 |
| 3 · 冻结、销毁和释放 | R05–R08。冻结与解冻消费目标 UTXO、逐一生成保持资产、数量及持有人身份的后继。销毁路径绑定目的域、收款人、费用和找零。测试储备释放原子消耗赎回事件，并分别控制铸造和释放暂停。 | 错钥、改量、换持有人、冻结期间支付和销毁、伪造销毁、错误找零及重复释放均被拒绝。冻结与支付竞争同一 outpoint 时只确认一方。释放失败后可重试同一请求。 |
| 4 · 可恢复的跨链闭环 | R09–R13。接入两链确认策略、事件补扫、对账、角色轮换、撤权和版本迁移。先用独立 BSV regtest 和测试储备跑通，再将同一验收矩阵用于跨链测试网。 | 端到端产物包含两链交易引用、证明、逐步供应与储备余额、失败原因。重启、乱序、重复投递和重组演练通过。分别定义跨链动作前回滚，以及动作后深重组的暂停与人工处置。 |
| 5 · 容量、优化和发布评审 | R14、X01–X04。先量共享验证器、父材料重复、解锁见证和节点策略，再调 Groth16 算术。分别测试 64→64、256→256 的共享父交易和不同父交易场景。 | 报告交易字节和每输入见证、出证、节点验证、钱包成本以及节点策略上限。正式参数、审计、升级演练与外部合作条件通过后，进入生产发布评审。 |

## 首个实现批次

1. 定义版本化的资产描述符及铸造／转账语句编码。生成字段级字节向量并记录域分隔、端序和哈希覆盖范围。先用最小 1→2 检查交易摘要和实际后继锁，保持大容量 fixture 作为后续基准。
2. 用两个互相独立的父证明做递归可行性验证，记录当前曲线、证明系统、电路约束数、出证时间和内存。比较现有电路内递归与内层递归加外层 Groth16 两条路径，外层仍必须约束内层验证结果及同一个交易语句。可行性试验结果决定阶段 2 的实现路线。宿主侧父证明检查可用于对照。
3. 为铸造权设计单事件标识和原子消费试验。事件身份取自经过认证的源域、储备合约及事件位置，重复签发共享同一事件身份。验证状态 UTXO 的创建、延续和防重复消费，单独评估串行化成本。

## 贯穿各阶段的验收样例

入金并铸造 1,024 最小单位，拆分为 640 和 384。冻结 640，验证支付被拒绝，再解冻并合并。用合并后的 UTXO 部分销毁 640，保留 384 找零，源链只释放一次 640。另以全额销毁用例覆盖无代币找零的交易。零费用用例中，释放后储备与流通均为 384，待铸造和待释放归零。

每个负例记录拒绝发生在哪一层。钱包的 SPV 验收依赖其采用的区块头链、交易包含证明及矿工对 L1 规则的执行。它对具体 vout 的认证与该输出的已知花费状态分别报告。持续地址封锁与全局转账暂停需在 X03 确认后确定策略新鲜度、失效行为及共享状态争用模型。
