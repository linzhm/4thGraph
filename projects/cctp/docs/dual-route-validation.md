# CCTP BSV 指令执行与验证构件验收

当前交付在 `cctp/bsv-bridge`。先验收 BSV 冻结与解冻，保留现有 Script 路径为对照。项目沿用 [协议规格](bsv-usdc-bridge-spec.md)、[能力清单](bsv-usdc-token-checklist.md) 和 [共同验收向量](../fixtures/dual-route-scenario.json)。向量记录整数数量、角色和交易位置。每个实现用自己的锁和实际 UTXO 构造线序交易。

## A · Script 强制执行规则

1. 把每个槽位约束到实际 vin、直接父 txid:vout、规范父锁及前序证明，逐一核对有序输出的状态、数量、satoshi、持有人与后继锁。
2. 保留现有连续性电路、公开声明和密钥。用独立证明认证父交易定稿字节、实际 verifier vin 和资金输出、规范输出边界及前序摘要。多输入消费同一个父交易时共享这份证据。首轮使用新的隔离发行锚。[独立绑定设计](parent-binding.md)
3. 共享验证器在节点验签时使用实际 `0x41` 或 `0x61`。钱包先定稿输入顺序、输出、金额、费用和找零，再生成预像并请求角色签名。持有人首轮签 `0x41`。独立节点按激活前、激活当块、后一块验收混用和错配，并单测管理配对 `0x43` 与 `0x63`。
4. 完成认证铸造至两侧释放的完整路径，验收重放、冻结竞争、重启和深重组处置。随后测见证瘦身、64→64 和 256→256。

## 验证构件与冻结小样

1. 通用 Groth16 层按验证密钥、公开输入和证明生成锁与见证。普通 Groth16 直接使用基础接口。电路产生 BSB22 承诺时选用承诺适配器。CCTP 制品编码和递归声明留在项目适配层。
2. BSV 绑定层用原生签名和节点验签认证实际交易。冻结小样用发行方 `0x41` 授权，固定公钥认证实际 `0x41` 预像。按实际有序 outpoints 选 token vin0，并核对唯一配对 vout0，把同一交易的 `0x43` 摘要重建到冻结声明。连续性验证器以及后续实验中的独立共享验证器都必须关联实际消费的指定锁。
3. CCTP 冻结电路验证同一笔认证交易中的后继状态。聪数、资产、数量、持有人和策略身份保持一致，冻结位翻转。第一轮用独立参数和测试发行锚，把交易绑定、公开声明和证明验证组合在同一个锁中。分别量出证时间、交易及见证字节、独立节点验收耗时和拒绝层。

### 验证器复用的条件

- Groth16 生成器及见证接口可跨电路复用。不同电路按各自参数生成锁。只有使用同一验证密钥、公开输入编码及约束关系的动作才能直接复用同一链上验证锁。
- 冻结和解冻共享「冻结位翻转且其余字段保持」的同一个电路。分离布局让 token vin0 核对发行方、实际 verifier vin1 和声明回执。verifier vin1 从实际有序输出取得同一份 32 字节公开摘要，再验一份证明。两个动作使用同一个锁身份，各自实际消费一个资金 outpoint。
- 量分离成效时对比 token 锁、共享验证锁、每个输入的见证、后继输出、发行准备及每个验证器资金交易。多输入只在一份声明确实覆盖所有实际输入和后继时计入复用。候选迁移规则优先考虑跨动作共用的后继字段约束和 MIMO 数量守恒。权限签名、实际槽位、交易承诺与现有双链结清仍在各自认证层核对。
- [2→2 数量守恒小样](../recursion/conservation/README.md) 已用同一链上验证锁完成独立父付款及后继共父付款。每笔只验证一份真实 Groth16。两个实际 token vin 仍各自验证持有人及声明，完整直接父材料由共享验证器认证。

原单证明探索分支 `cctp/groth16-rules-exploration` 从 `4e3b02294501afabf6d5b03490a8ce9bd4e452d1` 建立。保留其 `1→2` 电路和钱包构件，当前停止生命周期扩展。BSV 直接父交易的认证仍是见证瘦身目标。跨曲线递归及源链区块压缩暂停。

## 证据和比较

| 验收 | 需要记录 |
|---|---|
| 正例和拒绝项 | 提交、参数指纹、实际交易和区块引用、公开值、拒绝层与复现命令。覆盖共同向量中的假来源、错槽位、角色、锁、金额、收款人、旧证明、冻结花费和重复释放。 |
| 父材料与历史深度 | 固定直接父个数、输出规模和当前交易形状，逐代记录每输入见证。祖先原文合计应为零字节，见证只随直接父证据变化。与归档 25,742,267 字节的部分销毁并列，单列旧历史首次接入的链下出证成本。 |
| 容量与运行成本 | 完整路径通过后比较 64→64 与 256→256 的共父、多父、同持有人和多持有人。记录出证次数、出证时间、峰值内存、交易与最大输入字节、费用、节点策略及钱包确认结果。 |
| 双链验收 | 隔离 regtest 与公开测试网各保留两链证据。沿用受信 RPC 认证源链规范区块、最终性及指定入金日志，由授权签名器签发。沿 [Base Sepolia 候选计划](base-sepolia-plan.md) 准备资金、签名器、储备和适用的 BSV 节点。管理后台和临时域名在最终集成接线。 |

若父证明成本超出当前环境，保存最后一次真实出证或失败的复现材料，并分别记录 SHA-256、递归验证、节点约束与运行资源。已有 22,572,492 字节父交易的约 124 亿条约束是从小样外推的成本。任何 midstate 都需要认证真实前缀、已处理长度、规范输出边界和最后填充。[SHA-256 小样](../recursion/parentbinding/README.md)
