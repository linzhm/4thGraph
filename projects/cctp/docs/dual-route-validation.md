# CCTP 两条实现路线的共同验收

Script 主线在 `cctp/bsv-bridge`。单证明探索分支 `cctp/groth16-rules-exploration` 从 `4e3b02294501afabf6d5b03490a8ce9bd4e452d1` 建立，各自使用独立 worktree、测试发行锚和证明参数目录。两条路线都遵守 [协议规格](bsv-usdc-bridge-spec.md)、[能力清单](bsv-usdc-token-checklist.md) 和 [共同验收向量](../fixtures/dual-route-scenario.json)。向量记录整数数量、角色和交易位置。每条路线用自己的锁和真实 UTXO 构造线序交易。

## A · Script 强制执行规则

1. 把每个槽位约束到实际 vin、直接父 txid:vout、规范父锁及前序证明，逐一核对有序输出的状态、数量、satoshi、持有人与后继锁。
2. 保留现有连续性电路、公开声明和密钥。用独立证明认证父交易定稿字节、实际 verifier vin 和资金输出、规范输出边界及前序摘要。多输入消费同一个父交易时共享这份证据。首轮使用新的隔离发行锚。[独立绑定设计](parent-binding.md)
3. 共享验证器在节点验签时使用实际 `0x41` 或 `0x61`。钱包先定稿输入顺序、输出、金额、费用和找零，再生成预像并请求角色签名。持有人首轮签 `0x41`。独立节点按激活前、激活当块、后一块验收混用和错配，并单测管理配对 `0x43` 与 `0x63`。
4. 完成认证铸造至两侧释放的完整路径，验收重放、冻结竞争、重启和深重组处置。随后测见证瘦身、64→64 和 256→256。

## B · 每笔状态转换验证一份 Groth16

1. 首个里程碑是一笔实际 `1→2`。外部持有人 signer 对新版代币锁下的实际 `0x41` 摘要签名。签名以私有见证进入电路，公钥取自认证父输出。电路重算签名摘要，约束输入、资产、数值守恒和两个后继锁。共享验证器继续以固定公钥 PUSHTX 鉴别真实交易。每个被花费的代币输入关联同笔交易实际消费的指定 verifier UTXO。此阶段可使用独立父绑定；单独报告发行起点的证据范围。
2. 把直接父绑定、前序证明、规范 vout 和发行根纳入最终证明。使用完整父交易或认证前缀及后缀。最终公开声明在本笔 `scriptSig` 定稿前计算。本笔定稿 txid 用于后继的父证明。使用独立测试密钥和新锁，复用 BLS12-381 Groth16、BSB22 与递归验证构件。
3. 通过 `1→2` 的原生出证、独立节点正负例和费用实测后，推进真实异父 `2→2`、一次性入金铸造、冻结、解冻、销毁、释放和共享验证器双预像。源链最终性、BSV 销毁确认与外部释放的结清沿用项目已有策略。

## 证据和比较

| 验收 | 需要记录 |
|---|---|
| 正例和拒绝项 | 提交、参数指纹、实际交易和区块引用、公开值、拒绝层与复现命令。覆盖共同向量中的假来源、错槽位、角色、锁、金额、收款人、旧证明、冻结花费和重复释放。 |
| 父材料与历史深度 | 固定直接父个数、输出规模和当前交易形状，逐代记录每输入见证。祖先原文合计应为零字节，见证只随直接父证据变化。与归档 25,742,267 字节的部分销毁并列，单列旧历史首次接入的链下出证成本。 |
| 容量与运行成本 | 完整路径通过后比较 64→64 与 256→256 的共父、多父、同持有人和多持有人。记录出证次数、出证时间、峰值内存、交易与最大输入字节、费用、节点策略及钱包确认结果。 |
| 双链验收 | 隔离 regtest 与公开测试网各保留两链证据。公开验收沿 [Base Sepolia 候选计划](base-sepolia-plan.md) 准备资金、签名器、储备和适用的 BSV 节点。管理后台和临时域名在最终集成接线。 |

若父证明成本超出当前环境，保存最后一次真实出证或失败的复现材料，并分别记录 SHA-256、递归验证、节点约束与运行资源。已有 22,572,492 字节父交易的约 124 亿条约束是从小样外推的成本。任何 midstate 都需要认证真实前缀、已处理长度、规范输出边界和最后填充。[SHA-256 小样](../recursion/parentbinding/README.md)
