# 销毁及赎回

本设计落实 [协议规格](bsv-usdc-bridge-spec.md) 的 R07–R10。首轮采用持有人直接销毁、证明服务核验、储备侧释放的方式。发行方可以审批参数或代为组织交易。xReserve 的公开流程也是先在远端链销毁，再签发 burn intent 和提款证明。 [Circle xReserve 工作流](https://developers.circle.com/xreserve/concepts/how-xreserve-works#xreserve-withdrawals)

## BSV 销毁交易

1. 赎回请求明确资产、数量、目的域、USDC 收款人、费用和请求标识。需要审核时，在持有人提交不可逆销毁之前完成。
2. 持有人授权消耗有效、可赎回的代币输入。销毁分支承诺实际交易，在同一笔交易中生成可验证的销毁凭据和可选代币找零。
3. 共享验证器验证资产和来源、实际输出位置，以及「代币输入量 = 代币后继量 + 销毁量」。销毁凭据采用不可花费的输出模板。钱包不会把该输出识别为可流通代币。
4. 证明服务核对实际被验证的销毁凭据、交易及链上确认。BSV 侧可用「网络、txid、销毁凭据 vout」标识事件，正式赎回 nonce 按合作接口映射。

例如一次 1,024 枚的输入可生成 384 枚合法找零，以及承诺销毁 640 枚的凭据。篡改找零、收款人、数量、目的域、输出索引或证明均应被拒绝。

## 释放与故障恢复

储备适配器验证被认可的销毁证明和兑付参数，并原子地结清对应标识。已销毁待释放是单独的在途状态。广播失败、重复投递或操作重启时，用同一个标识查询或重试。已确认结清的请求只能返回原结果。

若业务需要先审核且保留退款权，可增加赎回托管 UTXO。销毁与退款竞争同一个托管输出，两条路径最多成立一条。发行方将代币收进普通钱包属于代办，代币在完成后续销毁前仍计入供应。冻结余额的试验策略是先解冻，再用相同销毁路径；其他处置权限需要单独定义。

## 验收

- 验证全额销毁、部分销毁和找零、重复释放与幂等重试。
- 验证假凭据、替换输出、错误网络、收款人篡改、未达到确认条件，以及链重组。
- 如果启用托管分支，验证退款和销毁竞态。
- 对账报告将销毁额从流通移入待释放，释放确认后移出待释放和对应的净储备。
