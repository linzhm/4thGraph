# SM2 SignedData 验收记录

[English](signed-data-acceptance.md) · [参考实现指南](README.zh-CN.md)

本记录说明付款适配器、通用验签和证书吊销评估分别验证哪些规则，以及每项规则有哪些
可复验的依据。付款适配器验证单个签名者对交易消息生成的直接签名。通用验签支持一个或
多个签名者，并同时支持直接签名和属性签名。两个入口均要求外层
`SignedData.version = 1`、内层 `SignerInfo.version = 2`。
[GB/T 35275-2026](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=28A18B702BDC318803E598F5E502E2CC)

## 验收结论

| 范围 | 结论 |
| --- | --- |
| SM2 付款 | 单签名者直接签名付款规则已通过验收。依据包括付款组合、单字节版本变异、独立签名器和节点交易重放。 |
| 通用验签 | 已验收本文所述的项目实现。验签要求至少一个受信任的签名者。属性签名默认按国标字段的原始 DER 验证，CMS 的签名输入须显式选择。 |
| PKI 吊销评估 | 以调用方选择的信任锚、提供的适用 CRL 和上级吊销状态证据为验收范围。 |
| 第 8 章编码 | 支持本文列出的算法参数编码及 PKCS #9 的 `messageDigest` 标识。开放属性和扩展的类型约束取决于其 OID 所对应的模式。 |

穷举结论适用于下文两个明确列出的笛卡尔积，以及有效封装的全部真前缀和单字节后缀。
其他规则由有针对性的用例举证。任意开放类型、完整的 X.509 证书及 CRL 规则仍取决于
相应的类型模式、应用约束和信任策略。

## 复现验收

先安装[参考实现依赖](requirements.txt)。在仓库根目录使用 Python 3.12 或以上版本和
支持 SM2、SM3 的 OpenSSL 运行。夹具生成专用测试密钥，并用 OpenSSL 核验签名。

```sh
PYTHONPATH=src:.:projects/p2pkh-sm2/reference python -m unittest -v test_signed_data_acceptance
```

运行 `bash projects/p2pkh-sm2/reference/verify.sh` 可在 BSV Node 1.2.3 和
chain-gang 中重放付款。脚本用 Cargo 构建 Rust 签名器，并调用 Python 签名器。
若已有 Rust 可执行文件，将 `SM2_SIGNED_DATA_SIGNER` 设为它的绝对路径即可跳过
构建。两种签名器均测试附带原文的 BIP143 和分离原文的 Chronicle OTDA 付款。
[Python 测试签名器](interop/python-signer/README.zh-CN.md) · [Rust 测试签名器](interop/rust-signer/README.zh-CN.md)

## 付款组合的穷举覆盖

| 维度 | 取值 |
| --- | --- |
| 内层 `SignerInfo.version` | 1、2、3 |
| 外层 `SignedData.version` | 1、2 |
| 内容 | 分离原文、附带已批准消息、附带其他消息 |
| 签名算法标识 | SM2-1、带 SM3 的 SM2 签名算法组合标识、SM3 |
| 授权 | 直接签名、属性签名、错误公钥、错误 SM2 用户标识、签署其他消息 |

上述五个维度产生 270 种组合。夹具逐项检查同一维度的取值互不重复、每个被访问的组合
都属于定义域、组合从未重复访问，并确认实际访问数量为 270。有限集合的子集与原集合
基数相同时，两者相等，因此这些断言可以发现遗漏、重复和超出定义域的组合。

只有外层版本 1、内层版本 2、使用 SM2-1 对已批准消息直接签名的附带与分离两种组合
应被接受。两种正例须返回从 OpenSSL 输出独立解码出的原始签名。其余 268 种必须抛出
`ValueError`。另有两条用例一次只修改一个版本字节，用来分别定位外层和内层版本错误。

## 可选元数据组合的穷举覆盖

这组用例固定付款签名有效，交叉附带、分离两种内容模式，以及
`certificates`、`crls`、`unsignedAttrs` 的四种状态。各字段可缺省、为空集合、
含一个有效成员，或含一个 ASN.1 NULL 成员，共有 128 种组合。夹具用同样的成员资格、
唯一性和基数检查证明覆盖完整。

证书和吊销列表可缺省、为空或含有效成员。未签名属性可缺省，出现时须至少包含一个有效
属性。由此得到 36 个接受组合，其返回值须与原始付款签名相同。其他 92 个组合必须报告
第一个不合法的字段。OpenSSL 独立生成并解析夹具中的证书和 CRL。额外用例交换两类
元数据、用空序列冒充证书和 CRL，并修改未签名属性的 OID、标签、长度和顺序。每次
绕过一个可选字段的验证都会使测试失败。

SM2 算法参数、签名值、时间类型及开放值。后续复审增加了证书名称属性的字符边界、
BMPString 和 UniversalString 的定长编码、合法辅助平面字符与非法代理项，以及
1999/2000 和 2049/2050 的日期与时间类型边界。证书序列号测试包含需要前置符号字节的
DER 整数，时间测试包含闰日、闰秒、小数秒及证书有效期边界。

## 第 8 章与 X.509 元数据

格式检查可以诊断含空 `SignerInfos` 的元数据样本。设置 `require_signer=True` 时，
结构检查要求至少一个签名者，通用验签同样要求至少一个。支持的扩展须使用唯一 OID，
省略 DER 默认值，并在扩展值中封装恰好一个符合类型要求的 DER 值。私有扩展及属性
需要提供声明它们的 ASN.1 模式。证书签名、信任路径及吊销判定还需要可信的应用输入。

| 方面 | 验收依据 |
| --- | --- |
| 证书与 CRL 版本 | 覆盖证书版本 1、2、3，CRL 版本 1、2，以及版本对唯一标识符、扩展的限制。版本 2 证书用 `asn1crypto` 构造，在原始证书字节上验证。 |
| 证书主题及 CA 扩展 | 空主题须配非空且标记为关键的 SAN。CA 须有非空主题、关键的基本约束、SKI 与证书签名用途。AKI 和 SKI 为非关键扩展。验证策略映射、名称约束、策略约束的位置、值和边界。 |
| 证书中的名称和分发点 | 检查主题与颁发者备用名、CRL 分发点、最新 CRL、信息访问扩展的非空约束，以及四种规定标识符的 PrintableString 编码和关键性。 |
| CRL 扩展 | AKI 和 `cRLNumber` 采用非关键扩展。增量指示符和签发分发点为关键扩展。编号字段接受最多 20 内容字节的非负 DER 整数。 |
| 吊销条目与分发点 | 只有增量 CRL 可以使用 `removeFromCRL`。检查原因、失效日期、间接颁发者、正数序列号、非空吊销列表以及签发分发点各布尔默认值。 |
| 已声明的私有类型 | 对证书、CRL 和吊销条目，验证私有类型的正确编码、错误类型、SET OF 顺序和缺少模式时的独立错误。 |

独立签名的补充样例覆盖策略和名称约束（27 个）、备用名与分发点（19 个）、
标识符类型（16 个）及 CRL 发行者、吊销日期和默认字段（18 个）。这些样本先独立签署
并验证，再装入零签名者封装，单独检验元数据格式。
[GB/T 20518-2018](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F7B410A1B0C06206E5FFB0FBFEE82C75) · [ITU-T X.690](https://www.itu.int/rec/T-REC-X.690/en) · [RFC 5280](https://www.rfc-editor.org/rfc/rfc5280)

## 完整 CRL、增量 CRL 与快照

增量 CRL 的 `cRLNumber` 须大于 `BaseCRLNumber`。调用方先确定颁发者及适用
范围，再比较同一序列中的签发时间和编号，或检查完整列表能否与增量列表配对。
序列夹具穷举 36 种组合并对照两种输入顺序，配对夹具覆盖 15 种相对时间和编号位置。
单独覆盖角色颠倒、不同颁发者、名称字符串编码与规范化、分发点一方缺失和两方不相同。

`merge_crl_revocations` 检查配对与 AKI，按证书颁发者和序列号将增量条目应用到完整
列表上。对于间接 CRL，首条默认使用 CRL 颁发者，后续条目继承前一条的颁发者，直到
关键的 `certificateIssuer` 指定新颁发者。存在多个不同目录名时，由调用方选定
已认证的颁发者。重复条目及不受支持的关键扩展会使合并失败。

合并矩阵组合四种完整列表状态与五种增量操作，验证添加、替换、保留和解除吊销。
可选的同时间、同编号完整 CRL 须与合并快照的条目、原因、日期及适用范围一致。
六张测试证书分别经完整列表、完整与增量列表、同时发布的完整列表验证，得到 18 个
OpenSSL 判定，用于对照快照结果。[RFC 5280 §5.2.4](https://www.rfc-editor.org/rfc/rfc5280#section-5.2.4)
· [RFC 5280 §5.3.3](https://www.rfc-editor.org/rfc/rfc5280#section-5.3.3)

## 吊销签名、适用范围与证书路径

`verify_crl_signature` 使用经调用方认证的颁发者证书验签。
`merge_crl_revocations` 收到 `issuer_certificate` 后，用同一证书公钥验证
完整、增量及可选的同时间完整列表。SM2 验签使用未压缩公钥、原始 `tbsCertList`、
DER 签名值和配置的用户标识。测试分别修改公钥、颁发者名称、签名用途、证书与密钥
标识和 SM2 用户标识，并用独立的 RSA 和 SM2 签名作对照。

`assess_certificate_revocation` 在指定时间组合经过认证的快照。适用快照中的有效吊销
条目足以判定 `revoked`，与其原因代码无关；原因掩码只决定覆盖范围。只有可用快照覆盖全部八种原因时，缺少吊销条目才判为 `unrevoked`。
其他情况返回 `undetermined`。测试覆盖含起点的 `thisUpdate`、不含终点的
`nextUpdate`、过期或尚未生效的列表、在较早的暂缓记录之后解除吊销、相互冲突的版本、直接与间接
颁发者、分发点名称、CA 与终端实体范围及原因掩码。补充的 OpenSSL 对照覆盖匹配与
不匹配的适用范围、已吊销、尚未生效和已过期的 CRL。

提供显式信任锚后，目标证书与 CRL 签名证书的路径均由 OpenSSL 验证到同一信任锚。
证书有效期以两端均包含的方式检查。测试覆盖缺少中间证书、篡改证书签名、名称约束、
最长路径、CA 密钥用途、关键扩展、显式策略以及不同根证书。对同名但密钥不同的根及
已过期的中间证书也有独立用例。

设置 `require_chain_revocation=True` 后，选中路径中的中间证书及 CRL 签名证书
都必须具有可信的上级吊销状态证据。每份证据来自该证书已验证的直接上级。检查从
信任锚向终端推进，以发现循环依赖、证据缺失或过期以及证书已吊销的情况。该选项
要求上级使用直接 CRL。目标证书的评估也支持取得认证的间接 CRL。
[RFC 5280 §6.1](https://www.rfc-editor.org/rfc/rfc5280#section-6.1) · [RFC 5280 §6.3.3](https://www.rfc-editor.org/rfc/rfc5280#section-6.3.3)

## 签名属性与算法参数

第 8 章将签名属性定义为 `signedAttrs [0] IMPLICIT SignedAttributes`，签名输入为该
字段的 DER 编码。按 X.690 §8.14，本项目默认使用原字段的构造型 `[0]` 标签
（`A0`）。CMS 使用通用 SET 标签（`31`），需显式指定
`signed_attrs_encoding='cms-set'`。独立 OpenSSL 签名在两种内容模式中验证相同属性
成员在两种编码下互不替代。

本项目采用 PKCS #9 的 OID `1.2.840.113549.1.9.4` 标识 `messageDigest`。
每个含签名属性的签名者须有恰好一个该属性，且属性值须是一个 32 字节的原始 DER
OCTET STRING，等于消息原文字节的 SM3 摘要。矩阵覆盖相邻 OID、只出现在未签名
属性中的摘要、封装字节的摘要及长度错误的摘要。标准规定摘要值和消息的关系，本文
列出的 OID 是项目采用的互操作标识。

| 字段 | 算法 OID | 接受的参数 |
| --- | --- | --- |
| `digestAlgorithms` 与 `SignerInfo.digestAlgorithm` | `1.2.156.10197.1.401` | 省略或精确的 DER NULL `05 00` |
| `digestAlgorithms` 与 `SignerInfo.digestAlgorithm` | `1.2.156.10197.1.401.1` | 省略或精确的 DER NULL `05 00` |
| `SignerInfo.signatureAlgorithm` | `1.2.156.10197.1.301.1` | 省略或精确的 DER NULL `05 00` |

算法标识来自 GB/T 33560，参数字段语法见 GB/T 20518。附录 A.1 展示了封装中显式
DER NULL 的形式。上述表格是本项目采用的接收规则。矩阵覆盖含附带和分离在内的
全部 64 种接受组合，并对各字段的算法标识检查七种错误参数编码。嵌入的 SM2 证书
和 CRL 则按其签名算法规则省略参数。
[GB/T 33560-2026](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=9BF813CEEAFB58A19534FF861465D8FD) · [GB/T 20518-2018](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F7B410A1B0C06206E5FFB0FBFEE82C75)
· [RFC 2985 附录 A](https://www.rfc-editor.org/rfc/rfc2985.html#appendix-A) · [RFC 5652 §5.4](https://www.rfc-editor.org/rfc/rfc5652#section-5.4)

## 附录 A.1 历史样例

出版样例的外层版本为 1，内层版本也是 1。内层位于印刷页 15、字节偏移 860。两处
无密钥 SM3 及一处 SM2-1 算法标识均带 DER NULL。正文第 8 章表 3 要求内层版本为 2。

夹具根据正式出版内容核对转录样例的字段偏移，用证书公钥和明确配置的 SM2 用户
标识，在 OpenSSL 中独立验证其 24 字节原文上的历史签名。嵌入证书的两处签名算法
标识也含显式 DER NULL。正文的内层版本规则由另一组独立用例判定：以合法的版本 2
付款封装为起点，只改版本字节，再验证两个入口都拒绝该封装。
[GB/T 35275-2026](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=28A18B702BDC318803E598F5E502E2CC) · [十六进制转录](https://www.gm7.org/archives/108338)
