# P2PKH-SM2

## 开发入口

**[钱包 SDK 快速上手](docs/sdk.zh-CN.md#quickstart)** · [v1.3.0 候选版](#v130) · [统一钱包 SDK](../../sdk/README.zh-CN.md#quickstart)

选择原始 SM2 签名器或 SignedData 签名器。符合条件的付款会自动选择更短的 OTDA 解锁编码。

[协议规范](docs/spec.zh-CN.md) · [安全分析](docs/developer.zh-CN.md#security) · [复现与验证](#开发复现与输入输出分析) · [交易成本](#完整交易与栈测量)

付款方可以用收款人未压缩 SM2 公钥的 HASH160 锁定一笔 BSV 输出。花费时，
持有人公开该公钥，并为当前输入提供一次 SM2 签名。Bitcoin Script 使用 SM3 计算 SM2
用户标识摘要 ZA 和消息摘要，然后验证 SM2 签名，并通过 PUSHTX 和原生
`OP_CHECKSIG` 将授权绑定到实际的花费交易。

## 使用场景与取舍

已有 SM2 签名服务的钱包可以评估 P2PKH-SM2。提供原始 SM2 接口的服务直接返回签名。使用 GB/T 35275‑2026 服务时，可按钱包的可信签名者配置处理单签名者的直接签名 SignedData 封装。SDK 在链下核验封装，将提取出的 64 字节签名写入交易。接入时应明确调用服务的哪个签名接口，并核对消息和用户标识。[签名接口](docs/sdk.zh-CN.md)

如果付款会新建 SM2 输出，用相同的输入输出数量比较 BIP143 和 OTDA。钱包会为符合条件的 Chronicle 花费重建签名预映像，缩短 OTDA 解锁脚本。每个新输出携带所选模板的完整锁定脚本。[重建实测](#otda-constructor)

## 项目版本与锁定模板

v1.1.0 为首个公开版本 v1.0.0 的锁定模板 `1` 默认启用 OTDA 重建。v1.2.0 引入模板 `2`，v1.3.0 候选版引入模板 `3`。钱包按上一输出的完整字节识别并花费三种模板。

| 项目 | 取值 |
| --- | --- |
| 收款标识 | 65 字节公钥 `04 \|\| X_BE32 \|\| Y_BE32` 的 HASH160 |
| SM2 用户标识 | 固定的 ASCII 字符串 `1234567812345678` |
| 锁定脚本 | 模板 `1` 为 144,925 字节，模板 `2` 为 131,565 字节，模板 `3` 为 125,616 字节 |
| 解锁脚本 | BIP143 为 291 字节，无配对输出的 OTDA SINGLE 为 294 字节，其他 OTDA 模式的长度随交易变化 |
| 解锁栈 | 签名预映像、未压缩公钥，以及 64 字节的 `r \|\| s` 签名 |
| 交易签名模式 | BIP143 和 Chronicle OTDA 均支持 ALL、NONE、SINGLE，每种模式均可选用 ANYONECANPAY |

当前源码包含[模板布局](versions/v1.0.0/layout.json)、[SM2 标准向量](versions/v1.0.0/sm2-standard.json)、
[完整付款向量](versions/v1.0.0/spend-all.json)和 [16 个签名预映像](versions/v1.0.0/sighash-modes.json)。[v1.0.0 发布页](https://github.com/linzhm/bsv-script-lab/releases/tag/p2pkh-sm2-v1.0.0)

## v1.3.0 候选版

点加和倍点对每个坐标执行一次 `OP_MOD`，保留模 SM2 域素数的有符号余数。验签器先拒绝投影坐标 Z 为零的情况，再将 X、Z 转为非负余数，检查签名对应的两个可能域横坐标。每个新输出节省 5,949 字节。同一份 OTDA ALL 预映像可重建三种模板的输出。

| 实测字节数 | v1.2.0 | v1.3.0 | 变化 |

| 锁定脚本 | 131,565 | 125,616 | −4.5% |
| BIP143 ALL，两进两出整笔 | 263,834 | 251,936 | −4.5% |
| OTDA ALL，两进两出整笔，启用重建 | 287,524 | 275,608 | −4.1% |
| 上述 OTDA ALL 交易的单输入解锁脚本 | 12,136 | 12,127 | −0.1% |

## 生成锁定脚本

在仓库根目录运行下面的命令。示例中的哈希仅供演示，创建实际输出时请换成收款人的
公钥 HASH160。

```sh
cd projects/p2pkh-sm2/reference
python3 generate_lock.py --owner-hash160 000102030405060708090a0b0c0d0e0f10111213
python3 generate_lock.py --owner-hash160 000102030405060708090a0b0c0d0e0f10111213 --format raw > scriptPubKey.bin
```

第一条命令输出模板编号、脚本字节数和该收款脚本的 SHA-256。第二条命令将锁定脚本的
原始字节写入文件。也可以通过 `--public-key` 提供未压缩的收款公钥，生成器会先验证
公钥，再计算其哈希。

## 签署并验证付款

单输入付款可用 `sign_payment`，它使用 BIP143 ALL（`0x41`）。交易已构造好时，
可用 `sign_input` 为不同输入分别选择签名模式。签署 OTDA 输入时，请提供实际花费时
的 Chronicle 激活状态。钱包调用外部签名器，验证返回的签名后再构造解锁脚本。

SM2 签名。封装的外层 `SignedData.version = 1`，内层 `SignerInfo.version = 2`。
Python 和 Rust 命令行签名器均使用专用测试密钥。[SignedData 接入指南](reference/README.zh-CN.md#signeddata-付款接入)

## 开发复现与输入输出分析

在仓库根目录启动 Linux 节点复放。测试环境需要 Python 3.12、Rust 和支持 SM2、SM3 的 OpenSSL。

```sh
cd projects/p2pkh-sm2/reference
python -m pip install -r requirements.txt
bash verify.sh
```

接入 SignedData 的钱包通过可信配置固定签名公钥和完整的 DER 颁发者与序列号。签名前核对被花费的 outpoint、金额、确认数和收款锁。国标封装由链下适配器处理，解锁脚本带的是提取后的原始签名。

两进两出时，BIP143 ALL 的解锁为 291 字节。OTDA ALL 的原始解锁把两个完整输出放进每个输入的签名预映像，解锁增至 290,109 字节。新增第三个输出时，除 144,925 字节的输出锁本身外，两个已有输入的解锁也会变长。下表分项列出这些开销。交易版本和 SignedData 的两层版本值分别按各自的编码规则处理。

## 输入输出边际与生命周期

每个边际单元格为 **新增整笔字节（输出锁定脚本 / 输入解锁脚本 / 其余序列化字节）**。其余字节包括金额、outpoint、序列号和 CompactSize 等字段。上一输出脚本列用于说明被花费的锁，该脚本长度属于此前创建 UTXO 的交易。生命周期从原生 P2PKH 入金开始，以原生 P2PKH 退出，周转列在两者之间增加一次项目内转付。

## 重建 OTDA 输出

构造器是 `scriptSig` 的一部分，模板 `1` 使用 12,703 字节，模板 `2` 使用 11,816 字节，模板 `3` 使用 11,807 字节。模板 `2` 和 `3` 从初始编码实际复制的指令中选出可复用片段，并把高频片段放在靠近栈顶的位置。构造器逐字节重建签名预映像，把收款人的 HASH160 填入各个适用输出。签名回调接收与原样编码一致的消息和 SM2 用户标识。构建子交易时使用最终已签交易的 ID。

Chronicle 激活后，版本 2 的 OTDA ALL 交易可以按原顺序重建匹配的输出。配对 OTDA SINGLE 可以重建同索引输出，并保留预映像中前置的空输出。两种模式均支持 `ANYONECANPAY`。其他模板的输出按原字节写入。BIP143、NONE、无配对 SINGLE、版本 1 及体积未缩小的交易继续使用原样解锁。[SDK 选项](docs/sdk.zh-CN.md) · [构造器与生成方式](reference/README.zh-CN.md#otda-constructor)

| OTDA ALL 场景，单位为字节 | 原始解锁 | 重建解锁 |
| --- | ---: | ---: |
| 两进两出整笔 | 870,194 | 316,018 |
| 首个输入解锁 | 290,109 | 13,023 |
| 新增一个输入 | 290,277 | 13,189 |
| 新增一个输出 | 434,814 | 145,022 |
| 入金与直接退出 | 290,794 | 290,794 |
| 入金、一次转付和退出 | 1,160,988 | 606,812 |

两种编码用相同的测试密钥和金额，均由 BSV Node 1.2.3 和固定版本的 chain-gang 验证。此表针对模板 `1`，用 `v1.1.0` 测量自动重建，用 `v1.0.0` 复现原样编码。
